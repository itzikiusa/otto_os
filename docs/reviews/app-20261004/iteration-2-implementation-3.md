## Rendered follow-up: draft revision was absent from detail

The first browser rerun successfully opened the real draft, proving R2-P3-03's opening repair, but then failed to find the leave confirmation after typing. This is a failed run (`/tmp/otto-review-product-focus-green.log` despite its filename), not a focus pass. Tracing the real API showed an additional existing defect: `create_draft`/`update_draft_body` write `kind: draft`, while `story_detail` requested only `kind: source`. Every local draft therefore returned `source: null`; Overview's `!!source` dirty prerequisite and `!src` seeding early exit disabled Save/leave protection and also hid previously saved bodies.

The complete repair selects the latest draft revision for local draft stories in `ProductService::story_detail`; imported stories retain their latest-source selection. Overview also seeds an absent-revision draft with its story title and an empty body and detects edits against that empty baseline. Rust and TypeScript `ProductStoryDetail` comments and the GET contract now state that semantic without changing the response shape.

Regression additions: `knowledgeRecovery.test.ts` executes the actual draftDirty expression with source null and verifies untouched=false, typed=true. The backend create-draft test requires a blank editable draft revision in the response; the existing update test requires the returned saved body and verifies reopening retains it even when a newer unapplied suggested revision exists. Root owns running these and rebuilding the isolated daemon for backend-aware browser checks. Newly owned paths are `crates/otto-product/src/{service,types}.rs` plus the narrow ProductStoryDetail contract and `ui/src/modules/product/types.ts` comment, recorded in the coordination note and communicated to role5. No backend/native runtime pass is claimed before the central results arrive.
