## Confirmed findings

### R15-01 — High: publication could substitute a later commit after proof validation

Observed path: `crates/otto-server/src/run_service.rs::open_pr` checked HEAD against proof, then awaited repository/account/Keychain reads and called `LocalGit::push`. `crates/otto-git/src/local.rs::push_with` resolved the live branch when invoking plain `git push`. Advancing branch A to B while credentials loaded therefore published B under A's proof. The persisted draft source branch was also not compared with the branch being pushed. The old regression moved HEAD **before** entering the publication function and could not detect this interval.

Coordinator repair independently reread: `check_proof_revision` returns the proven SHA and checked branch; draft source must match; `push_revision` passes immutable `SHA:refs/heads/branch`, suppresses follow-tags/mirror/submodule pushes and retains ordinary fast-forward rejection and existing AskPass/error classification. This closes revision substitution without force. Origin URL/configuration remains normal Git behavior and is not claimed immutable. New isolated bare-origin regression covers moving local HEAD, exact published SHA, no implicit tags, forward success and non-fast-forward rejection. **Source accepted; coordinator log `/tmp/postmerge-final-git-issues-isolated.log` records 481/481 tests passing, including the pinned-publication regression.** R15 identified that the initial tag assertion used a tag at the later unreachable commit; the coordinator strengthened it to point explicitly at proved A. That oracle refinement postdates the 481-test run. The server proof/draft fixture remains part of the final consumer gate.

### R15-02 — High: Stop did not cancel evaluator scoring commands

Observed path: `skill_eval.rs::run_skill_eval_core` delegated score-only work to `run_score_only_core` without the cancellation flag; `eval_score.rs::score_iteration` awaited test and lint commands sequentially. `cancel_run` marked the evaluation cancelled and archived managed PTYs, but these proof commands are subprocesses rather than PTYs. A long test continued after Stop and lint could start afterwards. Delete could remove an owned evaluation worktree while the command still used it. Generate-mode scoring had the same uncancellable await.

Correction requested from R14: cancellation must drop the scoring future, whose shared proof-command runner now owns and kills its process group; check before each command and preserve cancelled terminal state against background completion. A harmless temporary marker/sleep fixture should prove both descendant termination and that the second command is never launched. **Source repair accepted:** `score_iteration` and each command are cancellation-aware; dropping the future kills the owned process group; terminal persistence uses `finish_running` CAS. R14 log `/tmp/r14-combined-green.log` records the real command cancellation regression passing, including absence of the delayed child marker and lint marker.

### R15-03 — High: retry results did not invalidate or refresh promotion evidence

Observed path: `skill_eval.rs::retry_validation` wrote the new validation slot and legacy `iteration.score`, but left `iteration.scoring`, its composite and the persisted `Validator findings` proof artifact unchanged. `iteration_gate` used that composite and recomputed the old artifacts. A previously passed validator retried to a real blocker could consequently still pass promotion after the retry finished. Requiring every agent to be done alone is insufficient.

Correction requested from R14: invalidate promotion evidence at retry admission and refresh the review signal/composite from the final validator state and retained command/diff/human evidence. The final source serializes retries per evaluation, rereads after the lease, atomically clears published scores at admission and recomputes the Review artifact and composite from final state. Review-artifact write failures now propagate. **Source repair accepted.** R14 combined gate passes the persisted failed-retry and atomic invalidation/cancellation fixtures; the post-lease snapshot and write-error refinements postdate that run and need the final gate.

### R15-04 — High: failed validators with no findings produced passed review evidence

Observed path: failed validation agents are persisted as `status="error"`, `passed=false`, score zero and an empty findings array. `eval_score.rs::review_signal` flattened only findings, ignoring validator status; an empty array became a passed Review artifact and full review score. Thus failure to obtain a verdict was represented as successful verification even though the visible agent slot showed an error.

Correction requested from R14: an errored/incomplete required validator must produce incomplete/failed review evidence and block ordinary promotion; retain explicit human force/waiver semantics. Include a positive control for genuinely completed zero-finding validators. **Source repair accepted:** `review_signal` requires every validator to be done and emits failed evidence/zero review score otherwise. The R14 combined gate passes the real persisted-artifact regression with a completed-zero-findings positive control.

### R15-05 — Major performance: validation-group cap did not bound expanded provider work

Observed path: `skill_eval.rs::validate_eval_request` capped `validations.len()` at 16, while `run_skill_eval_core` expanded every `validation.providers` entry into a seeded row and `JoinSet` task. Each task also cloned the complete precomputed Git diff. One validation containing thousands of repeated valid provider names passed admission. Cost is O(P) tasks/rows and O(P × D) copied diff bytes for P provider entries and D diff bytes. SessionManager's 12-live-session limit does not bound this already-created work.

Correction requested from R14: bound the expanded sum of `max(1, providers.len())`, reject blank/duplicate providers and check expansion before persistence or spawning. Include boundary/over-limit and empty-provider fallback controls; matrix admission must account for the per-cell expansion. **Source repair accepted:** expanded validators are capped at 16 with blank/duplicate provider rejection before launch; matrix aggregate work is capped at 256 steps. New boundary and over-limit tests await the final gate. No large-allocation stress probe was performed.

The initial and retry precompute paths also buffered all `git diff HEAD` output before cloning it, even though the prompt retained only 6,000 characters. Bounding provider count alone does not bound D; capture must be bounded at the subprocess reader as well. Both producer and retry now call `validator_diff`, which captures at most 24,004 bytes through `LocalGit::diff_text_capped(Some("HEAD"), ...)`; the Git subprocess is terminated at the output bound. This preserves the tracked HEAD comparison while bounding per-task cloned data. Final compiled coverage remains pending.

### R15-06 — High: reading a score-only implementation diff staged the user's working tree

Observed path: `skill_eval.rs::impl_diff` requires workspace Viewer and executes `git add -A` in `iteration.worktree_path` before reading `--cached` diff. Its comment assumes a disposable evaluation worktree. However `run_score_only_core` stores the actual workspace path for `target.kind="working"` and the supplied existing directory for `kind="path"`. A viewer opening that evaluation's diff consequently stages unrelated user edits in the real repository. Its 200 KiB response cap was applied only after buffering the entire patch.

Correction requested from R14: make the GET genuinely read-only and bound Git output at capture; include an isolated score-only working/path fixture with existing staged and unstaged changes and assert the index is unchanged after the GET. No actual user repository was used to establish this finding. **Source repair accepted:** the GET now calls `LocalGit::working_diff_with_untracked_capped`. It preserves tracked HEAD comparison, adds untracked patches without staging, disables optional index locks/external diff/textconv, and bounds tracked output, aggregate untracked bytes, filename window and file count. Valid `--no-index` exit 1 is accepted; other failures propagate. Unborn HEAD computes the repository-format empty tree without writing objects. New fixtures compare raw index bytes plus staged diff, cover ignored/new files and unborn HEAD, and assert a large Unicode patch is capped. These new fixtures await the coordinator gate.
