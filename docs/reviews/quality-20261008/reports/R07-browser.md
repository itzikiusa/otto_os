# R07 — Browser, reader/live modes and agent interaction

**Verdict: approve the repaired paths with verification limits.** Six confirmed findings repaired (one blocker, four major, one minor); no 9.8/10 claim. Baseline: merged `a0bd718b9fbc008d72c164ce643a24ed78e6368c`, branch `review/quality-20261008`. Findings are pre-existing at that snapshot; no evidence isolates them to PR94. Other reviewers' concurrent changes were preserved.

## Findings and repairs

1. **Blocker — annotation origin tab crossed workspace ownership.** `crates/otto-server/src/routes/browser.rs:934,1178`. An editor could POST a mark in workspace A with an existing workspace B `tab_id`. Creation checked only A; sending that mark to the editor's own session subsequently loaded B's tab title without checking B's workspace. The persisted reference and foreign-title read are source-traced; no real user data was accessed. Creation now returns the same 404 for absent/foreign origin tabs, and sending older records filters title lookup by workspace. Contract/type comments updated. Regression `annotations_only_accept_tabs_in_their_workspace` checks foreign/missing rejection, zero inserted rows, and own-workspace success.

2. **Major — remote reattachment navigated the page again.** `ui/src/modules/browser/live/RemoteLiveView.svelte:173`, server `browser_live.rs:496–526`, runtime `live/runtime.rs:315–325`. Every reconnect POST included `url`; server explicitly navigates an existing session when that field is present. Thus reconnect/tab return could erase unsubmitted form/scroll state. The UI now sends viewport only; the server already uses the saved tab URL for new sessions. Named remote-live E2E asserts initial and reconnect bodies omit URL while keeping viewport, and exercises automatic reconnect plus the closed-session Reconnect action. Mock transport verifies the actual wire payload; it does not claim real Chromium form persistence was exercised.

3. **Major — stale summaries crossed tab/workspace ownership.** `ui/src/lib/stores/browser.svelte.ts:399–430`. Same URL in a second workspace or tab let an older request publish its summary there; an earlier request also cleared the newer request's busy flag. Five initial deterministic tests failed before repair. Summary requests now capture workspace generation, active tab and reader generation, are controller-owned, abort superseded work, and are invalidated on selection/navigation/close. Same-URL workspace switch, tab switch, leave-and-return, overlapping requests and deselect cleanup regressions now pass.

4. **Major — cancellation leaked reader gates and live CDP pending replies.** `crates/otto-browser/src/lib.rs:747,839`, `src/live/conn.rs:41,181`. Reader gate release happened only after the awaited render; cancelled tasks skipped it. Live CDP pending entries similarly remained when the requesting future was dropped before a reply/timeout. Repeated cancelled distinct requests caused O(N) retained keys/waiters for the service/connection lifetime; normal success tests did not cover this. RAII guards now return retained state to the number of genuinely active calls. Tests abort a running reader request and a pipe-backed CDP screenshot call, await cancellation and assert empty maps; another test checks one dropped gate holder cannot evict an active render's gate. Browser crate 116/116 tests and all-target clippy pass. No long-duration RSS/throughput benchmark was run.

5. **Major — reopening Browser did not load its saved reader tab.** `ui/src/lib/stores/browser.svelte.ts:98–130`. `loadTabs()` set `activeId` without invoking selection/page load; BrowserView had no general reader-load effect. Reload therefore showed a selected tab/address but an empty reader until clicking the tab. Initial/restored selection now follows `select()`, and old workspace tabs clear immediately. E2E reloads the real UI with a saved tab, verifies reader content, and repeats across light/dark schemes. Failed tab-list loads also previously became a silent empty list; they now show the shared inline LoadState and Retry (`BrowserView.svelte:788`). A separate 503/retry E2E confirms recovery to saved content.

6. **Minor — cancelled reader transitions retained busy/error state.** `ui/src/lib/stores/browser.svelte.ts:153–160,185–207,221–228`. New-tab/deselect and live transitions invalidated the page sequence but did not clear `loadingPage`, so the old fetch's finally block could no longer clear the spinner. They now clear reader busy/error state and live-mode/open transitions invalidate in-flight reader content. Deselect regression failed before repair and passes afterwards.

## Review coverage and cost model

Deep source paths: browser store and API callers; BrowserView native/remote selection, overlay poll ownership and autofill; ReaderView sanitized rendering/mark composer; tab strip, notes rail, AskBar and credential-panel caller search; RemoteLiveView reconnect, generation-tagged bitmap pump, navigation and approvals; reader service extraction/cache/query bounds; live runtime open/reattach/process cap/idle sweep; live CDP dispatch, viewer queues/flow, session attach/input/screenshot/close; guard proxy, request verdict cache, installer and Lightpanda lifecycle; browser tab/annotation/summary/send/ask/credential routes, live route rechecks and login throttle. `CredentialsPanel.svelte` has no production caller found; its unguarded async state is not reported as a reachable shipped defect.

Seams inspected: state browser repositories for origin/tab persistence, same-workspace session ownership before send/ask, netguard before reader fetch and live requests, source fencing helpers, native autofill domain recheck, UI command summarize caller. The excluded R02 command-execution candidate was not investigated or retried.

Sized bounds: reader input 2 MiB; service cache 32 entries/32 MiB, UI cache 16 pages; selector result 500 matches, 16 KiB serialized HTML per match and approximately 1 MiB total; native webviews MRU capped at four; live viewer frame window two plus newest pending frame, viewer output queue 64, incoming input queue 256; origin verdict cache 1024; login throttle 10,000 domains with three attempts/minute. These are source-enforced bounds, not measured production latency claims. Existing capped nested-page/query tests ran with the browser crate. Internal CDP event/output channels and proxy connection concurrency are not globally bounded; actual sustained-memory/backpressure behavior under a flooding page was not measured, so this report does not certify flood resistance.

Architecture: the reader/live backend split, pure protocol/geometry/flow reducers, and UI store separation fit the codebase. The fixes keep ownership with the existing store/service instead of introducing new public abstractions. BrowserView and RemoteLiveView still combine substantial native/network/UI orchestration; no independent refactor was imposed without a demonstrated second change requiring it.

## Limits and scores

Scope inventory covered the owned domain, but this is not an exhaustive line-by-line proof of every installer, CDP method, pure input conversion, test and CSS rule. Real native WKWebView geometry/overlays, actual Lightpanda/Chromium processes, genuine remote page login, persistent profile cookies, multi-user live revocation under load, cancellation at every install/CDP lifecycle boundary, tablet/RTL/Warm-theme visual combinations, long-page heap/latency baselines and flood/soak measurements remain unverified. Existing pure/unit/mocked browser checks cannot substitute for those. No native screenshot claim is made.

Scores are provisional review judgments of the repaired, inspected surface, with the above coverage limits: **correctness 8.8/10; performance 8.3/10; design 8.7/10; UX 8.7/10**. Remaining native and scale validation prevents a defensible 9.8 claim. Do not average these into a whole-product certification.
