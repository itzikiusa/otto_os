## Findings repaired

1. **High — revoked MCP authority survived asynchronous waits.** `crates/otto-mcp/src/service.rs:984`, `client.rs:268`, `service_preflight.rs:5`. A call passed server/tool/policy checks, waited for credentials or a client admission slot, and could execute after disable/revocation. The previous final check covered resource access only and preceded transport queueing. A deterministic held-credential fixture produced `Executed` after the server was disabled. The final transport hook now reloads server, tool, allowlist, policy and resource permissions after admission, and again after a new handshake; it checks before/after a safe stale-session retry. Changed configuration requires a new request/client; newly required approval/dry-run stops delivery. Denials rewrite the existing pre-execution audit row as denied and do not mark transport health unhealthy. Six governed cases cover server disable, tool disable, allowlist deny, policy deny, new approval requirement and changed command. Client tests prove no transport opens after queue-time revocation and no `tools/call` reaches the fixture after handshake-time revocation.
2. **High — unavailable configured MCP credentials silently fell back to empty credentials.** `service.rs:373`. Missing, unreadable, corrupt or incompletely persisted credential blobs previously produced an uncredentialed client (potentially using a command's default account). Resolution now fails closed with recoverable guidance, before creating a transport. Red/green test covers missing blob, malformed JSON, missing advertised key and non-string value, followed by successful discovery with a valid fixture credential. Secret-store-error handling is source-reviewed, not separately fault-injected.
3. **Medium — a partial MCP secret update erased the omitted map.** `http.rs:488`. Updating secret environment values replaced omitted secret headers with `{}`, losing credentials. PATCH now preserves the omitted map, replaces an explicitly supplied map, and lets `{}` explicitly clear it; supplying both maps allows recovery from unreadable prior data. Real router test proves header preservation across env replacement and clearing. Contract and TypeScript comments updated together. Concurrent competing PATCH requests were not stress-tested.
4. **Defensive identity hardening — channel key omitted transport.** `crates/otto-channels/src/bridge.rs:34,634`. A single Bridge's cached key could alias equal workspace/chat/thread IDs on different adapters. Shared key now includes channel, used consistently for routing and commands; cached sessions also undergo metadata matching. A red/green unit test demonstrates isolation for equal Telegram/webhook IDs. **Composition-root follow-up disproved the initially suspected current-production Telegram↔webhook exploit:** webhook and Slack/Telegram use separate Bridge instances, and native Slack/Telegram IDs occupy different formats. This is a strengthened abstraction invariant, not a confirmed production cross-transport defect. No external channel service was contacted.
5. **Medium — a stalled room WebSocket handshake had no timeout.** `ui/src/modules/rooms/room-client.ts:38`. The silence watchdog started only after `onopen`, leaving a hung upgrade in Connecting indefinitely. It now also starts when the socket is constructed. Fake-timer regression fails before the change and verifies close/disconnected/retry after the 10-second handshake limit.

The four reproduced defects and the identity-key weakness existed in the merged source; none is attributed to PR #94 without a historical introduction trace.

## Follow-up findings repaired

6. **Medium — `/new` released ownership before persisted detachment.** `bridge.rs:97,740`. A concurrent message could recover the old session while metadata update waited. Detachment now retains the conversation guard through the write, map eviction and mirror cancellation; errors return actionable retry guidance instead of claiming success. The deterministic persisted-state barrier test failed with the original gap (`routing entered before metadata was detached`), then passed with the guard retained. The helper uses the same lock as real message routing. Manager metadata update emits a nonblocking broadcast; mirror cancellation only flips its flag, so neither re-enters the conversation lock.
7. **Medium — channel inbound tasks and per-session turn backlog were unbounded.** `admission.rs:39,71`, `slack.rs:790,915`, `telegram.rs:648,669`, `bridge.rs:1190`, `routes/channel_webhook.rs:57`. Admission now reserves at most 256 total / 64 per integration / 8 per conversation ordinary turns, with the owned permit retained through queued and running work. Eight separate quick-command slots preserve `/stop` and recovery under ordinary overload; only the existing non-edited quick commands can use that reserve, and its exhaustion is tested. Eight separate busy-notice permits bound rejection work. Slack acknowledges rejected work only after a delivered notice through a bounded completion channel, preserving heartbeat handling; failed/saturated delivery remains unacknowledged. Telegram handles only a contiguous accepted/delivered-rejection prefix, retaining its suffix and avoiding duplicate admission on retry. Webhook returns 429 before spawning. The webhook and chat supervisors actually create **different Bridge instances**; `boot/tasks.rs:505` injects a cloned daemon-owned admission coordinator through `ChannelManager.with_admission` into the chat bridge. There is no process-global mutable counter. A real constructor fixture fills the webhook budget and proves the injected chat bridge is blocked while an unrelated bridge remains available.
8. **Medium — a transient integration read failure stopped healthy listeners.** `manager.rs:339`. The supervisor used to reconcile database errors as an empty desired integration list. It now retains the current generation and waits for the normal retry timer/shutdown signal. This repair is source/control-flow verified and covered by the package gate, but no live database-outage fault injection was run; do not describe it as a separately reproduced regression.

All repaired follow-up paths have passed the final channel package gate; the new webhook route unit and boot consumer rebuild are queued with R11's server build.

## Coverage and design assessment

Read the governance pipeline, client transport/admission/retry/cancellation, credentials, approval/autoapproval rules, MCP HTTP visibility/configuration and audit paths; sampled outward tool gateway/framing and UI bridge ownership/headless guards. Read channel supervisor/token lifecycle, Slack/Telegram receive loops and dedup, bridge lookup/commands/turn sequencing, webhook inbound/callback boundaries, attachment guards and mirror delivery/retry. Read room authentication/socket epochs/actions, bounded admission/chat, consent and recap cancellation/recovery/media bounds; frontend socket lifecycle, room page, media policy/capture, recap polling and disclosure flows. Supporting room unit suites cover stale epochs, budgets and consent behavior. This is explicit flow coverage, not a claim to have inspected every outward catalog entry or every settings control.

Architecture: authorization remains in the MCP service; the transport accepts a narrow asynchronous authorization hook and reports a distinct denial, avoiding a client dependency on SQLite/policy. The full live decision sits in a separate small `service_preflight.rs` module. The preflight and initial pipeline duplicate gate concepts, so future governance additions must update both; integration reviewers should check this seam. Channel identity now has one constructor shared by commands/routing. Admission is an injected, cloneable coordinator with RAII permit release; isolated fixture instances do not share counters. Transport-specific acknowledgement remains in the Slack/Telegram loops. Room reconnection reuses the existing watchdog rather than adding a second timer.

Rendered evidence: channel health with fixture Slack state, personal-agent room activity, real scoped MCP token rotation, MCP audit keyboard disclosure and 390px phone long-identity/error content in light/dark. Screenshots under `../evidence/R10/audit-*.png` were inspected: identities/error text wrap, focus is visible, and no horizontal page overflow occurred. The live room journey exercised guest invitation/admission, view-only forged-input rejection, role/control changes, chat isolation, stale grant rejection, end-room and preservation of the original running fixture process. Its first attempt failed because the test assumed `.xterm-rows`; the screenshot visibly contained the correct text rendered by WebGL. The corrected assertion uses the existing xterm buffer probe and passes with the real renderer.
