## Findings and repairs

1. **Blocker — refine-session ownership crosses users/workspaces.** Global vaults deliberately ignore provenance workspace in `VaultEngine::get_scoped`. The refine registry and persisted rehydration select only `(vault_id,note_path)`, while `agent_session::run_session_turn_with` resumes an existing session without checking its workspace/creator. Thus a second workspace editor submitting refinement to the same global note can reuse another user's conversation; GET exposes that binding and DELETE resets it. A handler-level regression seeds an exited session and persisted run, then exercises GET/reset for two users and two workspaces, without spawning agents. Correction implemented at `crates/otto-server/src/vault_docs_agent.rs:386,1373,1439` and `crates/otto-state/src/vault_docs_runs.rs:144`: scope the binding and persisted session selection by workspace and user, defensively verify actual session metadata before reuse, reject overlapping turns, and fence detached callbacks by turn identity. `update_refine_entry` at line393 prevents a late callback restoring a reset or overwriting a newer turn. Shared document and run-history visibility is a separate contract and remains global.
2. **Major — delayed UI mutations change a newly selected vault/run.** Production store/component tests reproduce delayed OKF toggle selecting the old vault, rename changing another vault's same-path tab, create opening a note in the new vault, old docs start replacing current selection and old disposition replacing another run. Selection-generation fences now keep results and follow-up refreshes with their origin (`ui/src/modules/vault/vault.svelte.ts:419,447,1030,1055`; `DocsAgentsView.svelte:253`). Additional branches covered by the same fence include rescan, trash and OKF indexing/validation.
3. **Major — refine dispatch outlives its workspace.** The before-content snapshot awaited without rechecking workspace, so leaving during that read still launched the old workspace agent; a later response could adopt its terminal in the new workspace. Two production-handler tests reproduce both branches. The drawer now checks workspace/vault/lifecycle ownership before dispatch and publication and remounts by workspace/vault/note; cleanup invalidates pending work (`ui/src/modules/vault/RefineDrawer.svelte:88,112,218`; `NoteView.svelte` keyed drawer).
4. **Major — unbounded watcher bursts and refresh starvation.** `watch.rs` queues filesystem events in an unbounded channel and accumulates every touched path until 300ms of silence. A sustained stream never reaches scanning; a large checkout/import retains arbitrarily many queued paths despite `MAX_CHECKED_PATHS=256` being checked only afterwards. Regression uses a temp vault, real SQLite engine and synthetic repeated notify events; no user paths. It failed before correction with zero refreshes after 1.5 s. `crates/otto-vault/src/watch.rs:33,53,112,194` now uses a 16-event queue, at most 256 retained paths, overflow-to-rescan signaling and a 1 s maximum burst; the same continuous-stream test passes. Root independent review then identified a late overflow-publication wake race in the first repair: consumer drains/swaps before callback sets the flag. A deterministic helper regression reproduced it; publishing a second Rescan wake after the flag closes that interleaving (`/tmp/r11-watch-overflow-red.log` → `/tmp/r11-watch-final-green.log`).
5. **Major — unbounded memory search `k`.** The public DTO accepts `usize`, then the service multiplies `k*4` before SQL and `k*3` while ranking. `usize::MAX` panics in checked arithmetic and wraps in release; large ordinary values fetch an arbitrary count of complete rows. Regression exercises default, ordinary, exact cap, cap+1 and max integer through the real service/SQLite. The service now clamps before forwarding/arithmetic to 200 result rows, at most 800 ranking candidates (`crates/otto-memory/src/service.rs:364`); Rust/TypeScript DTO comments and API contract agree.
6. **Blocker — private memory visibility bypassed by mutation and graph routes.** Ordinary GET already checks creator-only visibility, but PATCH/DELETE/governance operations do not. Workspace graph reveals private titles/IDs; links and entity-graph can expose private neighbors. Content dedup can return or revive another creator's private row. Isolated router/service regressions now cover denied mutation, no private IDs/titles/neighbor content, preserved state and owner/shared/root positive controls. Repair shares `MemoryService::get_visible` (`service.rs:208`) across HTTP and governance, with graph filtering before node limits and both endpoint checks (`crates/otto-state/src/memory.rs:818,896`; HTTP lines211–312; `crates/otto-server/src/memory_gov.rs:47,63,81,104,123`). Dedup rejects foreign-private/different-visibility collisions before return/reactivation (`otto-state/src/memory.rs:463`), malformed visibility is rejected at line325, and merge results retain the most restrictive source visibility. Automatic shared-folder write-through also exposed private bodies: real temp-folder red produced 2 files, corrected shared-only export (`service.rs:189`) produces 1 while retaining the private DB row. Previously exported real user files were not inspected or deleted.
7. **Minor — stale link previews.** A delayed preview loaded its path against whichever vault was current when the timer fired; same-path responses could overwrite a different vault preview. Cache entries also outlived content generations indefinitely. Three production-store regressions reproduce and repair vault/request ownership and generation invalidation while retaining the 100-entry cap (`ui/src/modules/vault/previewStore.svelte.ts:29,43,51`).
8. **Minor — cleared search resurrects an old query.** Clearing a pending query did not increment its request sequence or clear busy state. The old response repopulated results. Production-store red/green regression verifies no stale results and settled busy state (`vault.svelte.ts:1238`).

## Coverage and design assessment

Inspected file-backed Vault operations (guarded parent handles, compare-and-save hashes, revision/trash recovery, incremental scanner, watchers, prepared-note admission/cancellation), index hydration/publication, FTS search, graph caching/local BFS, OKF validation, memory service/remote/write-through/governance, docs run creation/list/retry/cancel/persistence/refine, and UI store/editor/recovery/docs/refine/search/switcher/preview flows.

Existing strengths traced: append-only recovery with optimistic restore hashes; index repair on partially completed writes; scans do not prune after incomplete walks; async expensive preparation is admitted and runs off executor threads; graph payload cache uses Arc without deep cloning and a per-vault entry cap; backlinks hydrate a 100-item context window; recovery lists page 200 entries through a path index; dirty notes survive failed saves and external-change conflicts. Global vault access is intentional, not itself a finding.

Architecture: filesystem truth and derived-index responsibility are separated well. Refine binding authority was misplaced in a global document key; a small scoped key and repository lookup resolves the concrete seam without introducing a new engine. The large VaultStore and docs agent module remain maintenance hotspots; no blanket rewrite is justified by line counts alone. Async ownership helpers are shared across the affected store operations.
