## Final server seam closure (verification pending shared build)

- **Major — mockup turn ownership, write acknowledgement and orphan poll.** `crates/otto-server/src/mockup_assist.rs` previously allowed overlapping requests to materialize/edit the same file, ignored preparation/final storage write errors, and detached its live file poll when the request future dropped. Three regressions failed in the coordinated server binary while seven existing controls passed (`/tmp/r12-mockup-red.log`). The repair claims an existing attachment before reading its session/source, holds the claim through completion, writes via a sibling temporary file plus rename with propagated errors, and aborts the poll on every owner-drop path. Agent-file reads now cap bytes during reading rather than relying on a racy metadata check.
- **Major — duplicate Blender renders during preparation.** `design_blender.rs` checked the recorded-job map before awaiting directory/script creation; two requests could both pass and consume the two process permits for one attachment. A pre-job admission regression failed (`/tmp/r12-blender-red.log`). A registry-owned claim now spans preparation, execution and output attachment, releasing on every error/drop path. Global process capacity remains two.
- **Major — concurrent Product conversation turns.** `chat.rs` loaded a missing session binding before await-heavy context assembly; overlapping first messages could each create a session. `refine.rs` similarly allowed two turns on one thread. New `studio_turn.rs` claims by conversation kind/workspace/id after authorization; handlers reread under ownership and hold the guard through provider execution and persistence. Session-binding persistence failures now propagate. Tests cover duplicate rejection, independent namespace keys and cancellation release. This finding is source-traced; no pre-fix executed race test is claimed.
- **Blocker — shared artifacts could reuse another user's execution identity.** Product host, mockup, Canvas and DesignAssist adapters forwarded stored session IDs into a runner that resumes the referenced session without creator/workspace authorization. The narrow `agent_session::require_owned_resume` helper queries authoritative persisted session metadata (also the source of live `SessionManager::get`) and fails closed for foreign identities. Only the four approved R12 adapters call it; other domains' runner policy is untouched. Four DB-backed fixtures cover allowed/missing/cross-user/cross-workspace for both running and exited rows. Public shared transcripts remain readable under the existing rules; foreign execution bindings now fail403. A new conversation/artifact may be needed to continue under a different user; no automatic identity reassignment is introduced.
