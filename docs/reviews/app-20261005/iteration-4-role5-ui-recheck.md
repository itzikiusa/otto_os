## Quality findings

### R4-R5-UI-01 — major — Failed provider change drains the new provider's model into the previous provider

**Location:** `ui/src/modules/settings/InsightsSettings.svelte:110–125`, `:134–138`; model-change callback `:66–70`; provider/model controls `:193–216`. Editable child controls: `ui/src/lib/components/ModelPicker.svelte:124` and `:133–138`.

**Intent:** Model IDs belong to their provider; the provider-change handler explicitly clears the model for that reason (`InsightsSettings.svelte:199–202`). Failed persistence must preserve a coherent retryable provider/model selection, not move a model to a different provider.

**Confirmed source trace:**

1. Begin with persisted `{provider:'claude', model:'A'}`. Select Codex in the real provider select. Its handler sends `{provider:'codex', model:''}` to `saveAgent`. Line 116 optimistically sets `cfg.provider='codex'`; line 117 sets `saving=true` while PUT 1 remains pending.
2. The provider select disables while saving, but ModelPicker does not. Its `provider` prop now reads Codex at line 213. The child's select and custom input have no disabled condition (`ModelPicker.svelte:124`, `:133–138`). Select/type a Codex model B there.
3. Hold PUT 1 longer than the 500 ms debounce. `onModelChange` schedules only `{model:B}`. The timer calls `saveAgent`, which sees `saving=true` and stores `queuedAgent={model:B}` at line 111. The provider identity is absent from that patch.
4. Reject PUT 1. The catch restores the previous Claude configuration at line 124. After clearing saving, `drainQueuedAgent` sends `{model:B}` through `saveAgent` again. Line 114 merges it with the rolled-back configuration, issuing PUT 2 with **`{provider:'claude', model:B}`**.
5. If PUT 2 succeeds, the UI adopts that mismatched configuration, clears `failedAgent`/the provider error, and flashes Saved. It never retries Codex with B. Even if PUT 2 is rejected, the outgoing provider/model pair was wrong.

This is reachable through the actual editable model control; it does not require invoking a handler that the UI disables. The existing provider-reset test covers cancellation of an older debounce when a provider change succeeds, not a failed provider change with an edit made during that request.

**Repair direction:** Associate each model draft/queued patch with the provider it was edited for. Following provider-write failure, retain a coherent failed provider+model draft and retry that pair, or keep it explicitly pending for user Retry. Do not merge a providerless queued model into whichever committed provider happens to survive rollback. Ensure both timer-pending and already-queued variants preserve the association.

**Regression required before repair:** Start a real handler provider write to Codex, invoke the still-editable model control callback with B, fire its debounce while PUT 1 is pending, reject PUT 1, and inspect every outgoing request. Assert no request pairs Claude with B, and the intended Codex+B selection is retained for a coherent retry. Also reject the provider write before debounce fires, and retain passing provider-success/model-save-failure controls.

### R4-R5-UI-02 — minor — Retry disabled state reads a plain, nonreactive timer

**Location:** `ui/src/modules/settings/InsightsSettings.svelte:65`, `:70`, `:188`.

**Confirmed source-level UI trace:** After a model save fails, the inline error/Retry block is mounted with `saving=false`, `modelSaveTimer=null`, and Retry enabled. Begin typing a new model. `onModelChange` changes the draft and assigns a non-null timer, but the disabled expression depends reactively only on `saving`; the timer is an ordinary `let`. The draft update drives ModelPicker, not this separate disabled attribute. During the 500 ms debounce, Retry therefore stays visibly enabled. Clicking it invokes `retryAgent`, whose plain timer guard correctly returns without action at line 142. Expected: Retry visibly disables while the new draft is pending, rather than accepting an apparently actionable click that does nothing.

**Compiler assessment, not executed:** The installed compiler source `ui/node_modules/svelte/src/compiler/phases/2-analyze/index.js:737–774` emits `non_reactive_update` when a reassigned normal binding is directly referenced from template markup. This variable now meets those conditions; the newly added disabled expression is the direct template reference. A Svelte warning is therefore source-predicted. No `npm run check` or compiler output was obtained by this reviewer, and no permanent deadlock or incorrect write is claimed: `saving` transitions re-evaluate the attribute when the timer fires, and the handler guard protects the write.

**Repair:** Make the timer handle reactive with `$state`, or expose a separate reactive debounce-pending boolean maintained on set/fire/cancel and use that in markup. Keep the execution guard.

**Verification:** Compile/typecheck the component, then mount it with a failed model save and controlled time. Type a replacement model and assert Retry disables immediately, remains disabled through active persistence, and becomes available again on the next failure. The plain function harness cannot establish this behavior.
