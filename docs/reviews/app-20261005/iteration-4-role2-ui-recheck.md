### Bounds and remaining cost, stated precisely

For a capped Git response with total byte allowance B and per-file allowance F, source computes `R=min(2B+64KiB,128MiB)` and `C=min(2F+64KiB,R)`. At B=4KiB, R=72KiB even when F is unlimited. Cut output charges C rather than zero; consumed raw bytes can overshoot R by one child before stopping. Up to eight child futures/outputs are in read-ahead, so R is not an exact peak-RSS or whole-request byte ceiling. The byte vector reader itself temporarily appends a64KiB chunk before truncating, and vector capacity/parse allocation also matters. This still removes accumulation proportional to all untracked patch bytes. Tracked patch capture retains its independent existing128MiB cap before parsing. Path/file metadata remains proportional to the number of files, as required to preserve the list.

**Do not claim all I/O is bounded by R.** `untracked_summary` at `local.rs:638` streams every omitted nonbinary text file to EOF to count added lines, retaining only a64KiB read buffer per serial file. Summary disk work is still O(sum of omitted text-file sizes), although patch child launches and retained patch bodies stop. Exact counts are preserved intentionally; CPU/disk latency remains to be measured on large repositories.

**Cancellation claim needs precise wording.** Overflow explicitly signals the process group in `read_stdout_capped` (`local.rs:321`), and timeout calls `kill_group`. Dropping buffered LocalRead futures drops `tokio::process::Child` with `kill_on_drop(true)` (`:1147`), which directly establishes child cleanup. The comment near the end of `append_untracked` says a process-group kill-on-drop guard remains armed, but this source does not show a separate process-group RAII guard. Therefore whole-group cleanup on generic stream drop is not certified here. Real default no-index commands disable external diff/textconv; no reachable production orphan was demonstrated, so this is a source-claim/measurement limitation, not an invented blocker. An isolated wrapper/helper cancellation control can verify that stronger property if required.
