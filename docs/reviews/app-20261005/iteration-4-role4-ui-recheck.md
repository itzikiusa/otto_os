## Behavioral quality findings

### R4-R4-UI-01 — major: workspace Discard leaves the old Goal Loop draft mounted and silently reassigns it

**Location:** `ui/src/modules/loops/GoalDefineForm.svelte:173`–`:177`; integration: `ui/src/modules/loops/LoopsPage.svelte:29`–`:31`, `:54`–`:55`, `ui/src/shell/App.svelte:1096`, `ui/src/lib/stores/workspace.svelte.ts:569`.

**Intended:** UX4-01 requires a workspace switch to preserve or explicitly settle the draft's ownership. Choosing Discard must not leave workspace A's goal ready to launch under B. A guard that merely returns true is insufficient when the component survives the switch.

**Confirmed hand trace:** Open New Goal Loop in workspace A; generate a valid goal with A's repository path and edit a criterion/budget. Choose workspace B. The real workspace store awaits the registered router guards. Accept “Discard goal loop.” `canLeaveForm` increments the generation and assigns `initialSnapshot = formState()`, but it neither clears the fields/draft nor invokes `oncancel`. Workspace selection sets `currentId = B`. The shell uses an unkeyed `<Page />`, so changing workspace alone does not replace LoopsPage. LoopsPage's workspace effect only loads B's list; `creating` stays true, so the same GoalDefineForm remains mounted. All A fields remain, now considered clean. Clicking Launch captures B at GoalDefineForm line 118 and creates an autostart goal in B with A's definition/repository. A subsequent navigation can also leave without another dirty warning because the discarded values were made the baseline.

**Actual / expected:** “Discard” acknowledges and retains A's draft under B. Expected: explicitly discarded draft closes/resets; Keep editing prevents the workspace change and preserves A's fields. This is a concrete integration defect hidden by a test that checks only the guard boolean.

**Repair direction / narrow ownership:** Prefer settling the form on accepted leave in `GoalDefineForm.svelte` (e.g. a single close/reset callback for the router and local Cancel paths), with no double callback. If settlement needs the page, change only `LoopsPage.svelte`'s creation-form lifetime/workspace identity logic. Preserve Claude's route-selection/read-write work; no broad shell keying change is needed. Keep the generation invalidation before later asynchronous completion. Do not merely reset the dirty baseline while retaining the old goal.

**Required regression:** Exercise the production router/workspace decision plus the actual persistent page/form lifecycle, or a mounted component test with that real behavior. A dirty goal in A → choose B → Keep editing must retain A and all fields. A → B → Discard must close or reset the form and make launching A's old draft impossible. Return B→A and verify the discarded form does not resurrect; test clean workspace navigation too. An assertion only on `mayLeave('') === true` does not reproduce this defect.

### R4-R4-UI-02 — major: a departed Goal Loop launch still replaces the current workspace's loop list

**Location:** `ui/src/lib/stores/loops.svelte.ts:144`–`:147`, especially unconditional `loadList(workspaceId)` at `:146`; list context reassignment `:53`–`:60`; component callback guard `ui/src/modules/loops/GoalDefineForm.svelte:153`.

**Intended:** A launch begun in A may finish in A, but late completion after leaving must not republish A into B's current view. UX4-01 explicitly requires pending launch ownership; guarding `oncreated` alone cannot undo store side effects that happened before it returns.

**Confirmed hand trace:** In workspace A launch a valid goal and hold the create POST. Switch to B through the approved leave path. LoopsPage requests and receives B's list, so `loops.listWs = B`. Now resolve the A create response. `LoopsStore.create` unconditionally calls `loadList(A)`, which immediately clears the list and assigns `listWs = A`. Its successful response passes its own equality guard and publishes A's loops, despite `ws.currentId` remaining B. Only after this does GoalDefineForm's `ownsForm` check suppress `oncreated`. Close the still-mounted form, or apply the UI-01 settlement repair, and B's page displays A's rows until a separate B reload occurs. This remains a defect independently of UI-01.

**Actual / expected:** Component navigation is suppressed, but the shared list moves to A under workspace B. Expected: the completed goal is returned to its original caller while only the currently owned workspace generation may trigger/publish a refresh.

**Repair direction / narrow ownership:** Reserve `ui/src/lib/stores/loops.svelte.ts` list/create ownership only. Apply the scheduledTasks store's two-generation pattern: a workspace generation prevents stale mutation-triggered refreshes; a request generation protects success/error/finally including A→B→A and reversed same-workspace responses. Preserve loop detail/polling behavior unless a separate verified defect requires changing it. No page URL-selection changes are required.

**Required regression:** Use the real LoopsStore with deferred API responses: load A, begin create(A), load/resolve B, resolve create(A), assert B's list and context stay B, no new GET(A) occurs, and create still returns A's created ID. Repeat A→B→A so an older mutation cannot publish into a replacement A context; cover stale list success/error/finally and reversed same-workspace responses. Pair this with the component callback/unmount case rather than mocking `loops.create` as one side-effect-free promise.
