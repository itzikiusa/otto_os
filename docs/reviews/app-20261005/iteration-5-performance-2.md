## Repair assessment and sized costs

- **R4-P2-PERF-01: prior aggregate retention/child-admission defect repaired.** `crates/otto-git/src/local.rs:2185–2324` consumes bounded read-ahead incrementally, charges captured bytes even when a file is omitted, and separates rendered budgets from raw-work budgets. Raw budget R is `min(2 × total_bytes + 64 KiB, 128 MiB)`; each child capture C is additionally bounded by the per-file budget and R. Eight buffered children bound read-ahead. Patch-body memory is O(R + 8C), rather than O(NB) for N untracked files of B patch bytes; parsing releases raw bodies between admissions. Tracked patch capture still has the existing 128 MiB subprocess ceiling and is charged before untracked admission (`:2164–2173`). This does not claim all request memory fits within the rendered 4 MiB budget. The five Git budget regressions passed in the inherited 106-test focused nextest run.
- **Explicit residual cost, not a newly discovered defect:** omitted files still require exact summary counts. `local.rs:638–688` reads text files in 64 KiB chunks; `:2315–2321` runs that work off the async runtime. For 100 omitted 4 MiB text files this remains approximately 400 MiB of disk reads and O(N) metadata, although patch subprocess launches and retained patch bodies are bounded. Therefore raw patch budget is not a bound on total filesystem I/O or response duration. The previous verification already records this limitation. Measure it before claiming input-independent responsiveness; no change to exact-count semantics is prescribed without evidence.
- **R4-P2-PERF-02: lifetime-history materialization repaired.** `crates/otto-state/src/workbench.rs:687–711` uses exclusive `seq < cursor`, ordered descending and clamped to 1–200 rows. The existing `(doc_id, seq)` primary key at `crates/otto-state/migrations/0165_workbench.sql:37–48` supports indexed seek paging. For N=50,000 stored revisions and P≤200, query work is O(log N + P), with O(P) metadata serialization. `ui/src/modules/workbench/HistoryPanel.svelte:44–45,97–126` requests and retains 100 rows, replaces pages, and uses a cursor trail rather than accumulating row bodies. Saves refresh one page. Comparison uses direct revision input/lookup rather than a lifetime-sized select. Cursor trail alone grows O(pages visited), not O(revision bodies), and resets on document change. Inherited HTTP tests include the 50k fixture, cursor stability after a save and oldest restore (3/3); MCP forwarding/catalog tests are 2/2; HistoryPanel handlers are 11/11. These prove functional bounds, not frame time or RSS.
- **API and database lifecycle:** the inherited 80/80 role2 handler suite covers workspace switches, dismissal/destruction, stale completions and cancellation. Workbench invalidates owner generations on close/destroy (`HistoryPanel.svelte:74–80`); database imports retain an AbortController and recheck ownership before retry (`ui/src/modules/database/ImportDialog.svelte:49–67,115–117`). Preventing stale writes is supported; these tests do not prove that every departed network operation is physically cancelled or that retained closures recover under sustained switching.
- **Existing capture/cache protections remain visible:** API body collection stops at 25 MiB inline and renders at most 512 KiB text (`crates/otto-server/src/routes/api_client.rs:3109–3145`). Broker schema-version cache admits at most 64 entries/8 MiB (`ui/src/modules/brokers/schemaVersionCache.ts:9–27`). Broker replay's inherited 6/6 MockCluster tests verify repaired payload semantics, not throughput. Prior Mongo cell/output limits, SQL preview batch limits, grid windowing and SFTP pooling remain inherited iteration-4 evidence; this pass did not re-audit their engines or measure remote throughput.

No new proven cost defect emerged from these bounded traces. Both previous major findings can close as implementation defects while their workload performance acceptance stays open.
