## Ranked findings

### P3-01 [major] Draft overviews load every imported transcript body before expansion — `crates/otto-state/src/product.rs:1717`

**What:** `list_transcripts` executes `SELECT *` without a limit and materializes all body strings. The endpoint returns that entire collection (`crates/otto-product/src/http.rs:1064–1071`); `ui/src/lib/stores/product.svelte.ts:443–451` retains it. Opening a draft Overview triggers this automatically (`ui/src/modules/product/OverviewTab.svelte:332–335`), although transcript bodies render only after expansion (`:1454–1474`). This is a separate collection from the previously repaired story-version summaries.

**Cost:** N is the number of pasted transcripts retained on a draft; B is their average body size. Opening/reopening the draft transfers, JSON-serializes/parses, and retains O(N × B) body bytes for collapsed items. This is one list request/query, **not N+1**. At 20 transcripts × 256 KiB the body payload alone is 5 MiB; at 100 it is 25 MiB; at 1,000 it is 250 MiB. These sizes are accepted through ordinary repeated transcript creation, which has no aggregate per-story bound (`http.rs:1081–1088`). JSON syntax, row/string copies and renderer representation add overhead, so these figures are payload arithmetic rather than RSS. The warm navigation path repeats the entire read; cost grows with historical content even when the user only edits the current draft or expands one item.

**Evidence: confirmed by source trace.** `ProductTranscript` includes `body` (`product.rs:337–343`), and the state list has neither a summary projection nor SQL pagination. An upstream per-request body cap would bound each insert, not the accumulated collection. There is a real consumer of collapsed bodies: the page find provider searches every transcript (`OverviewTab.svelte:1015–1038`). A repair must preserve that behavior explicitly rather than silently dropping search results.

**Fix/payoff:** Introduce a paged, thin transcript-summary list plus an authorized individual-body read; fetch/cache a bounded number of expanded bodies. Keep internal full-body retrieval available for context generation where requested, and provide search across stored transcript bodies or a deliberate bounded search-loading path that still reveals matching collapsed items. Update contracts/types together. Initial navigation becomes O(P × metadata bytes), independent of historical body bytes, with O(B) for an expanded item; P is the fixed page size. No automatic pruning or deletion is required.

**Required regression/measurement:** Seed 1, 20 and 100 transcripts with distinct 256 KiB bodies; measure endpoint bytes, first-paint latency, daemon/renderer CPU and post-close heap/RSS. Assert that opening a draft returns metadata only, expansion loads the correct body, page cursors have no duplicates/skips, and find can locate a match in a collapsed transcript beyond the first page. Include delayed expansion after story switching and failed-body retry. Run at N=1/3/5 concurrent active sessions as background load, then a sustained open/close cycle with comparable GC checkpoints. No such measurement was performed here.

### P3-02 [major] Large comparisons defeat context collapsing and mount the entire document twice — `ui/src/lib/components/DiffView.svelte:48`

**What:** The shared diff switches to “delete every line, add every line” whenever `beforeLines × afterLines > 4,000,000`, without checking equality or stripping a common prefix/suffix. Context collapsing runs only on equality operations (`:135–157`), so this fallback prevents it entirely. Design Hall's Changes view passes pretty-printed complete versions with `contextLines={4}` (`ui/src/modules/design-hall/CompareModal.svelte:99–101`, `:158–160`). Split rendering mounts every resulting row (`DiffView.svelte:239–263`), including both texts and their span elements.

**Cost:** N/M are lines in two supported artifact versions, including expansion caused by JSON pretty-printing. For equal-sized versions, the fallback starts at 2,001 lines. Two identical or nearly identical 10,000-line files generate 20,000 operations, 20,000 intermediate render rows and 10,000 split rows. Each changed split row has nine element nodes in the current template, approximately **90,000 DOM elements**, before text nodes and modal chrome. At 100,000 lines this approaches 900,000 elements. A 10,000-line JSON/text artifact can be well below 1 MiB and is below the explicit 25 MiB version cap (`crates/otto-design/src/format.rs:10`, `:194–210`). The DP allocation is bounded; output, retained row objects and synchronous DOM construction are not bounded by that DP cap. This is a warm user-triggered comparison path, not idle background work. Opening a second compare repeats it.

**Evidence: confirmed by hand trace; no observed freeze is claimed.** `fetchContent` retrieves the complete version via `resp.text()` (`ui/src/lib/api/design.ts:213`), not the 256 KiB inline-detail excerpt. The unconditional fallback supplies no `eq` operations, and split mode does not invoke word diff, so the cited cost is specifically row/DOM amplification rather than a claimed quadratic word-diff run. The existing small-input LCS bound is useful but insufficient to bound rendering.

**Fix/payoff:** Add a cheap equality path and strip common prefix/suffix before spending the diff budget. Independently cap visible/rendered rows and total diff work; use a bounded window or explicit large-diff fallback with a way to inspect/download the full sources. Do not silently label identical large inputs as all changed. A mostly unchanged 10k-line input can then render only its changed hunk plus context; disjoint inputs remain O(P) mounted rows with an explicit P-row window rather than O(N+M) DOM. Preserve line numbering and full-source access. Coordinate the shared `DiffView.svelte` behavior with the other feature partitions and Claude's presentation ownership.

**Required regression/measurement:** Compare identical, one-middle-line-changed, disjoint, and one-empty-side sources at 2,000, 2,001 and 10,000 lines. Verify correct equality/change labeling, bounded mounted nodes and access to omitted changes, not merely absence of an exception. Cover long single lines and multiline JSON expansion. Record Changes-tab latency, browser long tasks, heap and DOM counts in the actual Design Hall flow; repeat open/close and under 1/3/5 active sessions. Native WebKit remains a distinct acceptance target. No timing or memory result is fabricated here.
