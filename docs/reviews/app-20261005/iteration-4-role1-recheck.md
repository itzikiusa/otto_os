## Concrete source traces and quality assessment

**Live-handle protection.** An inactive History snapshot that now has a live PTY reaches `/resume`, not `/restart`. `ensure_live` at `manager.rs:3481` returns for the existing handle; competing inactive callers recheck under the same lock before spawning. A formerly-live row whose process has exited also reaches `/resume`, addressing the reverse-staleness follow-up. The HTTP test compares `Arc` identity for working/running/idle and stale-exited metadata instead of merely checking PID/status. Owner, other editor, admin/root and resource-denied cases are meaningful assertions. Archived/unsupported cases return Conflict. The route does not introduce an unconditional restart fallback.

**1,200-turn reachability.** For fixed 60-turn pages, page 0 requests no `before` and retains turns 1140–1199. Earlier stores request cursor 1140 at index 1 and replaces the body with 1080–1139; after 19 steps index 19 requests 60 and displays 0–59. Newer decrements the index and replays the recorded request cursor, ending at index 0/no cursor and 1140–1199. Only the current page's turns remain retained. Collapse deletes body/charge but leaves cursor metadata; reopen fetches the saved page. The unit fixture performs all 19 steps in both directions. Its bound assertion is only `<=300`, but the actual request uses 60 and the mounted three-page browser fixture asserts exactly 60 and the exact cursor sequence. No unreachable segment was found for this static transcript case.

**Shared consumers and late reads.** Two leases increment one reader's `refs`; the first release retains its body and the last aborts/deletes it. Release is idempotent. Collapse during a request aborts and nulls the controller. Reopening can start a fresh controller on the same reader; the old continuation fails `current()` and its `finally` cannot delete the replacement reservation because controller identity differs (`transcript.svelte.ts:469`, `:519`). Parent dispose additionally advances the epoch and releases all child bodies. Visibility return schedules refetch after activation. These ownership conditions were hand-traced, not executed here.

**Global admission and failure recovery.** A reader reserves a count slot before fetching. With eight pending reads, the ninth receives a retryable capacity error without starting a body download. Failure/final collapse releases the reservation; replacement reads retain the previous page charge until a successful replacement. The byte check subtracts the reader's old charge before adding the new one, so replacements do not double-count. Rejection keeps the previous readable page, with a retry target pointing at the failed destination. The synchronous charge check/update after each awaited read prevents concurrent successful publications from exceeding the retained-charge ceiling. The limit is explicitly an estimate of retained payload, not an RSS/transient-response bound.

**Failed-request ownership.** Title numbering, prompt, folder, model, account/network/browser choices, extra directories and scratch choice are captured once. For a workspace-bound retry, `NewSession.svelte:337` compares the captured ID with the current workspace before calling either store method. Both store methods resolve their target synchronously before their first await (`workspace.svelte.ts:1121`, `:1162`), so a workspace switch cannot occur between that check and target capture. A later switch during an outstanding request does not retarget its URL; subsequent failed members remain queued. Scratch retries explicitly retain scratch targeting. The test that mutates the form and compares the exact retried request exercises a real failure mode, rather than just reasserting the implementation's state layout.
