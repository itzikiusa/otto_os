# Redis Parity — Iteration 10: Batch Errors, Budgets, Live Gate & Final Consolidated Review (L13–L16)

Final review pass covering multi-command batch error stops, shared response byte/frame budgets, the `exec_command` `req_packed_command` fix for partial `EXEC` errors, the `redis_transport.rs` fixture fix, live Redis `7.4.11` (`127.0.0.1:26379`) verification (including a real 31s `BLPOP` blocking wakeup and bounded `< 500ms` `CLIENT LIST` cancel cleanup), and final consolidated lens scores with explicit evidence boundaries.

## Concrete Cases Traced, Fixed & Live-Verified

1. **Preserving Partial Runtime Errors Inside `EXEC` Array Replies (`redis.rs:491–529`)**:
   - **Live E2E Finding**: Running `MULTI\nINCR parity:tx:k\nLPUSH parity:tx:str bad\nGET parity:tx:k\nEXEC` against live Redis `7.4.11` revealed that `redis::Cmd::query_async::<RedisValue>(conn)` calls `Value::extract_error()`, which recursively inspects `RedisValue::Array` and turns the entire `EXEC` reply into `Err(WRONGTYPE)` whenever any element is a `ServerError` — discarding the sibling results (`1` and `"1"`).
   - **Fix**: Updated `exec_command` to call `redis::aio::ConnectionLike::req_packed_command(&cmd)`, unwrap any outer `RedisValue::Attribute { data, .. }` envelope in a loop, and convert only a **top-level** `RedisValue::ServerError(e)` into `Err`. Array elements containing `RedisValue::ServerError` are preserved in-place and formatted via `value_to_json` as `"(error) WRONGTYPE: ..."`, matching `redis-cli`.
2. **Fixture Reliability Fix (`redis_transport.rs:22–115, 542–553, 681–730`)**:
   - Updated `stream_and_module_object_detail_plus_batch_run_with_more_results_and_error_entry` to accept all 4 sockets (`1` cached connection for `object_detail` + `3` isolated connections for `driver.run()`), resolving the 10s handshake timeout from the earlier intermediate snapshot.
   - Made `peer` genuinely transaction-aware (`queued: Option<Vec<Vec<String>>>`), executing queued commands in order on `EXEC` (`[[11], ["5"]]`).
   - Added `configurable_response_timeout_governs_delayed_replies` to verify `Connection::from_stream_with_timeout` both aborts when a reply exceeds the configured transport timeout and succeeds when extended.
3. **Observed Bounded Cancel Cleanup & Genuine `>30s` Blocking Proof on Live Redis `7.4.11` (`tests/redis_e2e.rs`)**:
   - **Bounded Cancel Cleanup (`CLIENT LIST`)**: Cancelling an in-flight `CLIENT SETNAME otto-cancel-probe\nBLPOP parity:cancel:list 20` after `150ms` drops the operation-isolated connection; polling `CLIENT LIST` on live Redis `7.4.11` confirms `name=otto-cancel-probe` is removed within `< 500ms`.
   - **Real `>30s` Wall-Clock Blocking Proof**: `BLPOP parity:block:31s 40` with `timeout_ms: Some(45_000)` blocks across the 30s default transport threshold and wakes up cleanly at `31s` when a background task runs `RPUSH parity:block:31s after-31s`, returning `[["parity:block:31s"], ["after-31s"]]`.
4. **Multi-Command Batch Error Handling & Shared `ByteBudget` (`redis.rs:349–371`, `framing.rs`)**:
   - Multi-command batches share one 32 MiB `types::ByteBudget`, slice collections to `max_rows` before JSON conversion, offload `> 16,384` elements to `spawn_blocking`, and stop on the first command failure with `types::errored_batch_entry`.
   - `framing.rs` enforces pre-allocation wire limits (`32 MiB` bytes, `250,000` nodes, `32` depth) per operation.
